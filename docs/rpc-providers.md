# Read-only RPC providers

Sprint 5 router version: `sprint5-v1`. Set `SOLANA_RPC_URLS`, `BASE_RPC_URLS`, or `BNB_RPC_URLS` to comma-separated HTTPS URLs. Localhost HTTP is accepted for a local node. Earlier single-URL settings remain supported and public defaults remain fallbacks. Never commit `.env` or put credentials into documentation.

Each configured URL is SHA-256 hashed. SQLite stores the hash, a short provider ID, chain, type, probe results, safe log range, latency, error rate, recent successes and failures, cooldown state, and minute counters. It never stores the URL or query credentials. The router permits only the existing read-only RPC allowlist. No send, signing, wallet, or transaction methods exist.

The background worker probes every 30 minutes. Solana probes genesis and JSON-RPC batching. EVM probes chain ID, a historical block, a small `eth_getLogs` range, historical ERC-20 `decimals()` state, Multicall3, and batching. A successful empty log response proves the request works, not that the chain has no swaps. Probe failures set a capability to false; unknown stays null until tested. A historical-state probe at roughly 50,000 blocks back does not prove unlimited archive retention. The diagnostic page shows these limitations.

Routing prefers known capability, health, and lower latency. A provider known to disable logs is excluded from log reads; an archive-capable provider gets priority. Recent-block `eth_call` can still try a provider whose deep-history probe failed. Rate limits cause a 60-second cooldown. Three consecutive failures cause a bounded cooldown. Each call tries at most three providers. Per-provider and per-chain minute budgets default to 120 and 300 requests; exhausted budgets stop that request without implying missing chain data. Requests, batch calls, log queries, historical block reads, and fallback calls are counted. The foreground scanner can continue when a background log provider fails.
`RPC_CALL_TIMEOUT_MS` defaults to seven seconds so a slow endpoint cannot indefinitely delay a foreground scan. Probe calls use a five-second timeout and independent providers probe concurrently.

Historical log reads start at `FEE_LOG_BLOCK_CHUNK` (100). Success grows the range by 25% up to 16 times the configured size, capped at 5,000. Timeout/oversized-response failures halve it, never below one block. The learned range persists per provider. Persistent errors mark the fee job partial or failed with a reason; they never create an empty fee window.

[BNB Chain documents that its listed public mainnet endpoints disable `eth_getLogs`](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/). [Ethereum JSON-RPC defines block selectors and log filters](https://ethereum.org/developers/docs/apis/json-rpc/). [Geth documents batch semantics](https://geth.ethereum.org/docs/interacting-with-geth/rpc/batch). Provider behavior still requires live probes; documentation cannot guarantee a third-party endpoint's archive access or rate limits.
