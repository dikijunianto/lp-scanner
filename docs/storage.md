# Storage profile and disk safety

Run `pnpm retention --profile` for measured SQLite `dbstat` bytes by table and index, row counts, recent rows, and estimated daily bytes by table. This query scans the database and should run outside peak ingestion. Data health shows the database file, WAL, free disk, and estimated runway. Warnings activate below 50 GiB (`WATCH`), 25 GiB (`HIGH`), and 10 GiB (`CRITICAL`). Runway uses recent row counts and sampled row sizes; it is an estimate, not a guaranteed forecast.

Data health also estimates the post-version daily growth from full snapshots, compact snapshots, prices, and swap events. It includes approximate row and index overhead, so it is a forecast rather than measured file-size delta. The storage-growth readiness gate needs at least one hour of new rows and an estimate below 0.20 GiB/day. Disk runway stays on the conservative trailing-day estimate until 24 hours of post-version data exist.

On 2026-09-28 before Sprint 7 migration, the 8.35 GiB database had roughly 7.11 GiB in `pool_snapshots`, about 226 MiB in `fee_events`, and about 149 MiB in `price_observations`. Full snapshots were adding roughly 341,000 rows and 1.1 GiB per day. The primary mitigation is reducing new full JSON writes while retaining independent compact one-minute observations. Price observations with no source timestamp, or an identical source/timestamp/price already stored, are not appended. Historical source timestamps and provenance are never rewritten into artificial buckets.

The `pool_snapshots` primary-key index and `snapshots_pool_time` index each occupied about 155 MiB and appeared redundant. No index is dropped automatically. WAL remains enabled for concurrent read-only API access and core writes; SQLite checkpoints normally. `VACUUM` is manual and needs enough temporary free space. Do not run it during ingestion or while disk is scarce. Check query plans and the measured post-change growth rate before index maintenance. The target is below 0.20 GiB/day, subject to live measurement and research-integrity checks.
