# Priority bounded depth

Depth reconstruction remains in the background. The foreground scanner only applies cached observations that match its current tick/bin, liquidity/price state key, TTL and 2% price-drift limit. Watched pools and active signals lead the queue, followed by existing Tier 1 volume/activity priorities. Candidates with valid unexpired cache are skipped before the per-cycle limit is applied, so fresh cached pools do not consume work slots. Price or active tick/bin movement invalidates the key immediately. Current ±5% depth is the primary coverage measure. EVM tick reads cover ±5% to keep the bounded RPC workload focused; ±1% and ±2.5% use those ticks, while ±10% is unavailable unless a wider observation already exists.

Failures persist by pool and normalized reason: `NO_TICKS`, `RPC_UNSUPPORTED`, `TICK_READ_LIMIT`, `STALE_PRICE`, `POOL_STATE_FAILURE`, `INDEXER_STALE`, `PROVIDER_FAILURE`, or `UNKNOWN`. The data-health page shows BSC blocker counts. A missing reliable token price prevents a pool from entering the depth queue and is not reported as zero depth. BSC public RPCs can serve latest pool state while rejecting historical `eth_call` used for consistent tick reads; the scanner does not mix blocks to force a result. More capable RPC access may be required for the >70% HOT-pool target.
