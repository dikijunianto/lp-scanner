# Measured EVM fee windows

Base Uniswap V3 and BSC PancakeSwap V3 fees use confirmed pool `Swap` logs, decoded signed token amounts, the input token's decimals and a historical USD price near the event. The pool's immutable fee tier is read on-chain. The positive pool balance delta is gross trader input; `grossFeeUsd = inputAmountToken × inputPriceUsd × feeTier`. PancakeSwap V3's [extended Swap event](https://bscscan.com/address/0x2725ea4cfe5362949e02de3db380beb8d773781b#code) includes the actual per-swap protocol fee, which is subtracted in USD to estimate LP fees. Uniswap V3's [Swap event](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolEvents.sol) does not include the historical protocol-fee share; its reported fee is a **gross pool fee estimate**, not guaranteed LP capture. Per-tick fee rounding and price movement within the five-minute price bucket also limit precision.

The 5m, 30m, 1h, 4h and 24h windows are labeled `EVENT_DERIVED` only after the confirmed block cursor covers the full window and every contributing swap has a suitable price. Until then `volumeUsd` and `feesUsd` remain null with `UNAVAILABLE` methodology. Empty but fully covered windows correctly show zero. `startBlock` is the first contributing event block (null when no swaps); `endBlock` is the confirmed cursor block. `windowStart` and `windowEnd` are timestamps. These observations live independently in `fee_events`, `fee_cursors`, and `fee_windows` for later backtesting.

Logs are read in bounded chunks, at most three pools per EVM chain by default. Base scans up to 300 blocks per cycle; BSC up to 900 because its observed blocks cover much less time. Twelve confirmations and a persisted block hash guard reorgs. If the cursor's hash changes, the scanner discards that pool's derived fee history and restarts the cursor; pool snapshots remain untouched. Historical windows warm up naturally: a new installation does not claim a measured 24h window from one short RPC read. The public BSC dataseed rejects `eth_getLogs`, so fee ingestion defaults to a configurable public read-only RPC (`bsc-rpc.publicnode.com`); active liquidity retains the existing BSC RPC. Rate limits and provider availability can leave windows unavailable.
