# Event indexing and fee windows

The foreground scanner discovers pools and reads cached fee windows. A separate worker indexes confirmed Uniswap V3 and PancakeSwap V3 `Swap` logs, newest first. Each pool has a durable cursor, confirmed head, status, retry count, and failure reason. Failed jobs retry with exponential backoff. Watched pools get priority and a larger backfill budget. Public RPCs may rate-limit or reject `eth_getLogs`; set `BASE_RPC_URL` and `BSC_FEE_RPC_URL` to reliable read-only providers when needed.

The worker indexes only blocks at least `FEE_CONFIRMATIONS` behind the chain head. It checks the cursor block hash before every advance. A changed hash triggers rollback to the newest matching checkpoint, deletion of orphaned swaps and affected fee windows, and rebuilding of minute buckets. If no checkpoint matches, it resets that pool's cursor and reindexes. Removed logs and inconsistent block hashes are rejected. Unique `(chain, txHash, logIndex)` makes a replay idempotent. A batch and its cursor are committed in one transaction.

If a saved cursor is over one hour behind the confirmed head after an outage, the worker starts a new contiguous recent segment. It retains the old normalized swaps and prior snapshots, but does not claim the intervening gap was covered. The new segment backfills 1h, then 4h, then 24h from the recent head.

For each swap, positive `amount0` or `amount1` is the input paid to the pool. Input token units are raw amount divided by `10^decimals`; USD volume is input units times independent timestamped token USD price. Gross fee is volume × pool fee tier. Pancake protocol fee is decoded from its event and subtracted for LP fee; Uniswap V3 event data does not expose historical protocol-fee distribution, so its LP fee is a gross-fee estimate. Missing historical price leaves volume and fees null. Discovery quotes are never used for event valuation.

Event amounts, source block/hash, token prices, protocol fee, and confidence are stored. Recomputed minute buckets sum priced volume, gross fees, LP fees, swap count, and unknown-price counts. A 5m/30m/1h/4h/24h window sums only its minute buckets. It is `EVENT_DERIVED` only if the cursor covers the whole time interval and no included swap is unpriced. Zero swaps with complete confirmed coverage is a genuine zero. `uniqueTraderCount` remains null: V3 `sender` can be a router rather than a distinct human wallet, so counting those addresses would mislabel traders. Historical fee windows and prior snapshots remain stored.

Backfill status describes coverage, not profitability: `BACKFILLING` has less than 1h, `PARTIAL` covers at least 1h, `COMPLETE` covers 24h. A complete cursor still advances with new confirmed blocks. RPC gaps, historical price gaps, or stale heads keep individual windows unavailable rather than substituting reported TVL, volume, or fees.
