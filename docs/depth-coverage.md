# Bounded depth coverage

Depth methodology version `sprint5-v2` keeps expensive bin/tick reads in the background. The foreground scan only applies valid cached observations. Watched pools and active-signal pools refresh every two minutes, Tier 1 every five minutes, Tier 2 every 15 minutes, and Tier 3 every 45 minutes. Each background cycle selects stale or previously uncovered candidates instead of repeatedly reading the same first five. Per-chain `DEPTH_*_LIMIT` bounds work.

Meteora uses the official DLMM account coder to read only bin arrays spanning ±10% around the active bin. Each array is decoded once, and the same bin balances supply ±1%, ±2.5%, ±5%, and ±10% bands. Active-bin movement changes the state key. V3 reads bitmap words only around ±10% of the current tick, then reads initialized tick liquidity deltas through Multicall3 at the pool's observed block. The same decoded ticks supply all four bands. Caps on arrays, bitmap words, and initialized ticks prevent unbounded reads. An incomplete band remains null.

Each observation stores block/slot, calculation time, source, methodology version, and pair price at calculation. The cache key groups nearby tick/bin positions, liquidity, and token USD prices; small changes reuse a read, while material changes trigger refresh. Applying cached depth computes `abs(currentPrice / priceAtCalculation - 1) × 100`. Drift beyond `DEPTH_PRICE_DRIFT_PCT` (default 2%) marks depth `STALE` and clears the bounded values. Expired cache also clears current depth. Historical depth rows and snapshots remain unchanged. Price drift uses the scanner's latest observed pair price; it cannot detect movement between scans. Tick/bin reconstruction is a USD value in a fixed price band, not executable slippage or a personalized LP position.

Coverage is constrained by reliable prices, RPC access, array/tick caps, and worker limits. The diagnostic page separates observed current coverage from provider failure; no total-TVL fallback is used.
