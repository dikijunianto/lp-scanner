# Performance and operation

The scanner's scheduled foreground cycle is single-flight: another cycle cannot start while one is active. It performs discovery, bounded price lookup, shallow active-liquidity refresh, cached depth/fee lookup, and snapshot/signal persistence. Historical fee backfill, deep depth refresh, and outcome evaluation run separately. The background worker is also single-flight.

Price requests are batched by 50 DefiLlama assets and by chain for CoinGecko fallback; repeat source requests use short cache TTLs. Active-liquidity and depth refreshes use bounded pool limits. EVM fee logs use bounded block chunks and at most `BACKFILL_POOLS_PER_CYCLE` jobs per worker cycle. The persistent queue survives a restart. A failed job records the reason and retries later with capped exponential delay. More complete 24h coverage depends on RPC availability and historical USD prices, so a short successful scan does not imply fee coverage is complete.

Each scanner and worker run stores elapsed time, request counts, cache hits, and queue length. The coverage page exposes the latest numbers and worker lag. Request counts measure calls attempted by this process, not provider-side retries or bandwidth. `scanDurationMs` excludes background work. A source outage can stretch a scan beyond the normal budget because timeout handling protects against false data; degraded runs remain visible in run history. Tune pool limits or supply reliable read-only RPC endpoints if normal scans exceed 30 seconds or the fee queue stops advancing. No wallet or write-capable chain methods are used.
